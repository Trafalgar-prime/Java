# A cosa serve un trigger?

I trigger vengono usati per:

- controllare dati
- validare informazioni
- salvare log automatici
- aggiornare altre tabelle
- impedire operazioni non valide
- creare audit/storico modifiche
- automatizzare comportamenti

---

# Eventi che attivano un trigger

I trigger si attivano con:

```sql
INSERT
UPDATE
DELETE
```

E anche:

```sql
TRUNCATE
```

---

# Quando si esegue un trigger?

Può eseguirsi:

## BEFORE

Prima dell’operazione.

```sql
BEFORE INSERT
```

Serve per:

- controllare dati
- modificare valori prima del salvataggio
- bloccare errori

---

## AFTER

Dopo l’operazione.

```sql
AFTER INSERT
```

Serve per:

- creare log
- notifiche
- aggiornare altre tabelle

---

# Struttura di un trigger in PostgreSQL

In PostgreSQL un trigger ha SEMPRE 2 parti:

1. funzione trigger
2. trigger collegato alla tabella

---

# 1. Creazione funzione trigger

Esempio:

```sql
create or replace function controllo_stipendio()
returns trigger
language plpgsql
as $$
begin

    if new.stipendio < 1200 then
        raise exception 'stipendio troppo basso';
    end if;

    return new;

end;
$$;
```

---

# Cosa significa?

## returns trigger

Dice che la funzione sarà usata da un trigger.

---

## NEW

`NEW` rappresenta il nuovo record.

Esempio:

```sql
new.nome
new.stipendio
```

sono i valori nuovi che stanno per essere inseriti/modificati.

---

## OLD

`OLD` rappresenta il vecchio record.

Si usa in:

```sql
UPDATE
DELETE
```

Esempio:

```sql
old.stipendio
```

---

# NEW e OLD

| Operazione | NEW | OLD |
|---|---|---|
| INSERT | SI | NO |
| UPDATE | SI | SI |
| DELETE | NO | SI |

---

# 2. Creazione trigger

Dopo la funzione:

```sql
create trigger trg_controllo_stipendio
before insert
on contratto
for each row
execute function controllo_stipendio();
```

---

# Come funziona?

## before insert

Il trigger parte prima dell’inserimento.

---

## on contratto

Si attiva sulla tabella `contratto`.

---

## for each row

Esegue il trigger per ogni riga.

Se inserisci 100 righe:

- trigger eseguito 100 volte

---

# Esempio completo

## Tabella

```sql
create table dipendenti (
    id int generated by default as identity,
    nome varchar(50),
    stipendio numeric
);
```

---

## Funzione trigger

```sql
create or replace function controllo_stipendio()
returns trigger
language plpgsql
as $$
begin

    if new.stipendio < 1200 then
        raise exception 'stipendio inferiore al minimo';
    end if;

    return new;

end;
$$;
```

---

## Trigger

```sql
create trigger trg_stipendio
before insert
on dipendenti
for each row
execute function controllo_stipendio();
```

---

# Test

## Funziona

```sql
insert into dipendenti(nome, stipendio)
values ('Lorenzo', 1500);
```

---

## Errore

```sql
insert into dipendenti(nome, stipendio)
values ('Marco', 500);
```

Errore:

```text
stipendio inferiore al minimo
```

---

# Trigger AFTER

Esempio log automatico.

---

## Tabella log

```sql
create table log_dipendenti (
    id_log int generated by default as identity,
    messaggio text,
    data_operazione timestamp default current_timestamp
);
```

---

## Funzione trigger

```sql
create or replace function log_insert()
returns trigger
language plpgsql
as $$
begin

    insert into log_dipendenti(messaggio)
    values ('Inserito dipendente: ' || new.nome);

    return new;

end;
$$;
```

---

## Trigger

```sql
create trigger trg_log_insert
after insert
on dipendenti
for each row
execute function log_insert();
```

---

# Risultato

Quando fai:

```sql
insert into dipendenti(nome, stipendio)
values ('Anna', 2000);
```

automaticamente viene inserito:

```text
Inserito dipendente: Anna
```

nella tabella log.

---

# Trigger UPDATE

```sql
before update
after update
```

Esempio:

```sql
if new.stipendio <> old.stipendio then
```

controlla se lo stipendio è cambiato.

---

# Trigger DELETE

```sql
before delete
after delete
```

Qui esiste solo `OLD`.

Esempio:

```sql
old.nome
```

perché il record sta venendo eliminato.

---

# BEFORE vs AFTER

| Tipo | Quando |
|---|---|
| BEFORE | prima dell’operazione |
| AFTER | dopo l’operazione |

---

# FOR EACH ROW

Trigger per ogni riga.

```sql
for each row
```

---

# FOR EACH STATEMENT

Esegue una sola volta per tutta la query.

```sql
for each statement
```

Esempio:

```sql
delete from dipendenti;
```

- `FOR EACH ROW` → una volta per ogni record
- `FOR EACH STATEMENT` → una sola volta

---

# RETURN NEW

Nei trigger INSERT/UPDATE normalmente:

```sql
return new;
```

---

# RETURN OLD

Nei DELETE:

```sql
return old;
```

---

# Disattivare trigger

```sql
alter table dipendenti
disable trigger trg_stipendio;
```

Riattivare:

```sql
alter table dipendenti
enable trigger trg_stipendio;
```

---

# Eliminare trigger

```sql
drop trigger trg_stipendio on dipendenti;
```

---

# Eliminare funzione trigger

```sql
drop function controllo_stipendio;
```

---

# Attenzione importante

I trigger possono:

- rallentare il database
- creare loop
- creare operazioni nascoste
- rendere difficile il debug

Quindi vanno usati bene.

---

# Quando usare i trigger?

Usali quando:

✅ vuoi automatizzare operazioni database  
✅ vuoi controlli centralizzati  
✅ vuoi log automatici  
✅ vuoi audit storico  
✅ vuoi impedire dati invalidi  

Evitali quando:

❌ la logica può stare facilmente nell’applicazione  
❌ il trigger fa troppe operazioni  
❌ rischi dipendenze complesse  

---

# Esempi reali

## Audit modifiche

Salvare:

- chi modifica
- quando modifica
- valore vecchio
- valore nuovo

---

## Storico stipendi

Ogni modifica stipendio salva lo storico.

---

## Soft delete

Invece di cancellare:

```sql
delete
```

metti:

```sql
attivo = false
```

automaticamente.

---

## Controlli automatici

Bloccare:

- età negative
- stipendi troppo bassi
- date invalide

---

# Differenza trigger e procedure

| Trigger | Procedure |
|---|---|
| automatico | manuale |
| evento tabella | chiamata esplicita |
| INSERT/UPDATE/DELETE | CALL procedura |

---

# Differenza trigger e function

| Trigger Function | Function normale |
|---|---|
| returns trigger | returns tipo |
| usa NEW/OLD | no |
| chiamata da trigger | chiamata manuale |
